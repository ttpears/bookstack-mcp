# bookstack-mcp v5.7.1

This security patch tightens OAuth session authorization, HTTP input handling,
and one-time OAuth state/code consumption.

## Security

- Recheck both the subject and write role on every OAuth MCP request. A role
  change invalidates the existing session and returns 404, allowing the client
  to reinitialize with the correct credential and tool set. Requests from another
  subject remain forbidden and cannot invalidate the owner's session.
- Limit OAuth registration/token bodies to 64 KiB and MCP JSON bodies to 10 MiB
  by default. Set `MCP_HTTP_MAX_BODY_BYTES` to a positive integer for larger MCP
  requests. Body reads have a 30-second deadline. Limits apply to declared and
  chunked bodies; oversized requests return 413 and slow bodies return 408.
- Consume OAuth states and authorization codes atomically in memory and Redis,
  preventing concurrent reuse. Redis uses an atomic Lua GET+DEL script and does
  not require a newer Redis version or additional credentials.
- Return HTTP 400 for malformed MCP JSON without echoing request contents.

## HOL Guard

- Retain scan reports and registry summaries as downloadable workflow artifacts
  for 14 days.
- Show sanitized registry delivery status in the job summary and emit a warning
  when delivery is unconfirmed. A scanner pass still does not prove delivery;
  reporting remains separate from the security gate.

## Validation

- 51 application tests and five HOL reporting tests pass, including new coverage
  for role changes, oversized/slow bodies, and concurrent code redemption.
- A disposable Redis check with 60 concurrent consumers across three clients
  produced exactly one successful redemption and respected key expiry.
- The dependency audit reports zero known vulnerabilities.
- Package, Claude plugin, Codex plugin, and Gemini extension versions are
  synchronized to 5.7.1.
