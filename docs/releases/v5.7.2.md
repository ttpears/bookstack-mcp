# bookstack-mcp v5.7.2

This security patch stops Entra OAuth mode from treating app-only tokens as
signed-in users. See advisory
[GHSA-pwpj-h98w-6ppx](https://github.com/ttpears/bookstack-mcp/security/advisories/GHSA-pwpj-h98w-6ppx).

## Security

- A bearer token with no delegated scope (no `scp` claim, or `idtyp=app`) is an
  app-only (client-credentials) token. It is now refused unless it carries the
  app role named in `OAUTH_SERVICE_ROLE` and its client ID is listed in
  `OAUTH_SERVICE_APP_IDS`. Both are unset by default.
- An admitted app-only caller is read-only, whatever roles it holds.
- Delegated user tokens behave as before, including write mode by role.

## Upgrade note

If you call the server with client credentials on purpose, create an app role
allowed for applications, assign it to the caller, and set both variables when
you upgrade. Otherwise those calls are refused. See
[Allow an app-only caller](../SETUP.md#allow-an-app-only-caller-optional).

## Validation

- 56 application tests pass, including signed-token coverage for user, app-only,
  role-less, disallowed-app and unconfigured cases.
- Package, Claude plugin, Codex plugin, Cursor plugin, and Gemini extension
